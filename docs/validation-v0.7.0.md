## 真实原生 AI 对话开发

DSH alpha.2 原生聊天，界面显示 DeepSeek-V4.1-Flash / High。使用实际模型连接和工具回路，没有固定回答、工具响应替换或模拟模型。测试工作区与草图专用，没有修改用户已有项目。

输入是首页、登录页、商品详情三个页面，以及 Banner 细节；两条 navigation 来自首页登录按钮／商品卡片，一条 detail 来自 Banner 区域。任务要求先读图，再按节点读草图，在隔离目录生成 HTML/CSS/JS。实际 Agent 读取图摘要和四份结构，识别 Banner 是首页补充，没有单独建路由；通过真实工作区工具生成三份网页文件。最终源码见 [agent-site](assets/v0.7.0/agent-site/)，仅为浏览器演示，无真实身份验证、支付或订单后端。

不能省略的失败和纠正：

1. 前两轮模型读取 Banner 图片遗漏 nodeId，按根图读取被 revision 检查拒绝；没有退回错误图片。补充可复制的 `imageReadArguments` 与工具说明后，首次服务代码仍旧驻留内存；专用宿主重启加载新工具，第三轮明确复制参数，一次成功返回该节点 724×334 PNG（50672 字节）。模型实际描述了左侧文字／按钮和右侧“自然图形”占位框，并区分灰度图片与 purpose 的浅绿文字要求。
2. 模型首次自行多加两件商品，后续真实对话移除，最终只保留草图两件。首次自建 DOM 桩测试失败并反复扩展，经明确反馈停止并清理；这些桩结果不作为验收依据。
3. 模型第二轮仅检查 JS 的 hidden 切换就声称登录入口会隐藏；真实 Edge 仍显示两个控件。第四轮反馈后，模型在 CSS 增加 `[hidden] { display: none !important; }`。旧端口样式缓存未刷新，改用新本地预览端口确认新规则载入后复验通过。

我们实际在最终 Edge 网页确认：首页登录入口 → 登录页；空表单错误；体验账号登录 → 首页且登录入口隐藏；商品卡片 → 详情；数量改为 2，加入购物车，合计 ¥598；退出后登录入口恢复。Banner 留在首页。指定节点的 [实际图片工具参数与输出](assets/v0.7.0/image-tool.json) 来自展开的原生工具调用面板。没有验证真实后端或支付，也没有做模型质量、费用或速度比较。一次真实多轮案例不能证明所有模型或任意复杂图都可靠。
