# v0.6.4 双版本功能与数据保留验证

日期：2026-10-12（UTC）。源码基线：`8198e47`。宿主固定 DSH `0.2.1-alpha.1` / `0.2.1-alpha.2`；Excalidraw `0.18.1`、React `18.3.1`。Linux 云端、Node 24.19.0、Chromium 151。

## 结论与范围

验证对象是同一个 v0.6.4 tgz，通过两版官方 CLI 默认安装后，在真实 DSH 与真实 Excalidraw 中操作；不使用版本豁免，不修改宿主权限或用户 profile。测试分别隔离 DSH_HOME 与 XDG；模型响应由专用夹具提供，真实 DeepSeek 调用为 **0**。

下面是功能、协议和数据保留证据，不能代替 Windows、真实模型识别／推理质量、真实 429／网络超时、PTC／其他预设、其他插件组合和长期运行验收。

## 实际修复

alpha.2 原生主题服务增加字体配置，默认计算字体串为 296 字符。原 appearanceSchema 将字体和颜色均限制为 256，导致整批主题消息校验失败：宿主已进入深色，画板仍浅色。

v0.6.4 仅将字体上限设为 1024；颜色保留 256，仍拒绝分号、花括号、URL 与未知颜色键。公共 APPEARANCE_LIMITS 管理限额。两版实时主题切换不重载 iframe、不改变绘图 revision 的验证继续保留。

会话 owner 仍是不可变 header 的 `(id, createdAt, cwd)`；alpha.2 的有效 workingDirectory 不作为存储地址。草稿、批注、修改提议、视觉引用的 schema、域名／域版本、RPC v1、CAS 与恢复格式均未变，不运行迁移、不清空数据。

## 旧 v0.6.3 数据保留

在原始 v0.6.3 正式 tgz + alpha.1 隔离 profile 中，先通过现有流程生成已保存草图、独立分析与 Agent 两类批注、已解决状态、待应用提议、缓存 PNG，并保存视口和未发送文字。记录完整 JSON 快照与浏览器存储状态，再退出宿主。

在同一 profile／同一原点先安装 v0.6.4，用 alpha.1 重开；再退出并用 alpha.2 启动。两次逐字段相等检查通过；最终运行代码又在两版退出重启后分别复核通过：

- owner、revision、mutationId、两种内容摘要、全部场景、用途与时间。
- 独立分析、原生 Agent 批注、稳定批注 ID 与解决状态。
- 待应用提议、原场景备份、操作与版本。
- PNG 缓存状态、当前版本和原生图片工具读取。
- 视口、缩放／平移、本地未发送文字；主题切换不写绘图，原生只读不改快照。

测试期间没有导入替代草图或改写存储键。选区重点原本就是宿主内存状态，重启后重新设置；跨刷新撤销历史与宿主跨会话待发 PNG 恢复仍没有新增承诺。此结果不是 DSH 任意宿主日志／设置降级兼容保证。

`browser-dsh-compatibility.mjs` 的 seed／verify 模式可复验；directory 模式检查 alpha.2。脚本在任何分析前要求专用夹具的 scripted 标记，拒绝普通真实模型 profile；原始 browser-state（含本地测试登录状态）、日志与快照不提交。

## 本轮发现的测试问题与处理

保留失败事实，不把第一次失败改写成通过：

1. 分页列表已提交而锚点仍在下一 animation frame 测量，旧立即 count 得到 3 而不是 5；最终 alpha.2 的零建议阶段同样在下一帧清理前读到 5。分别等待实际 5／0 个标记后，两版复验通过，未改产品逻辑或放宽数量。
2. 旧修改脚本仍使用 v0.3 的“待确认”和预览 alt；当前界面为“待预览”及前后对照。更新定位，确认结果以持久化 applied 状态／scene／revision 验证，不依赖短暂提示文案。
3. 选区成功提示已是 status，旧脚本仍找 alert。当前过期重点会拒绝读，而旧夹具期待读取到 stale 摘要；旧固定响应重复尝试污染全局测试计数。已停机清理、添加错误响应和 12 次工具结果上限，不是产品自动轮询，也没有真实模型调用。
4. 视觉缓存已具备保存后预热，旧脚本假定第一次手动操作必定导出／注册。缺图阶段明确阻止测试缓存入库；后续检查当前 revision、第二次无额外导出／注册。画板关闭后继续尊重重点，不把全图读取作为绕过重点的预期。

脚本与夹具更新仅在 tests 下，未把模拟模型或额外 endpoint 加入生产 bundle。

## 可复现方法

1. 固定两版独立 CLI，初始化独立 Web profile，保持模型凭据为空。
2. `pnpm install --frozen-lockfile`，运行 typecheck／test／bundle／pack；保存 tgz 的 SHA256。
3. 分别用两版 CLI 正常 add 同一 tgz，不做版本豁免；将 tests 中已有 browse-picker／mock-model／mock-native-agent 及测试模块复制到各自安装 profile，避免从源码路径解析错宿主版本。
4. 依照 [既有浏览器测试准备](validation.md) 启动隔离宿主，DSH_SMOKE_URL 仅在本地传递，不打印或提交；逐个运行表中脚本。
5. 旧数据测试：DSH_COMPAT_MODE=seed 在 v0.6.3 记录；退出／升级后 DSH_COMPAT_MODE=verify，保持同一 DSH_HOME、存储与浏览器原点。DSH_TEST_OUTPUT 指向本地忽略目录；alpha.2 专项使用 directory。不要在日常 profile 加载这些夹具。
6. Windows 与真实模型依 [清单](windows-acceptance-v0.6.4.md) 另行验收；记录宿主／插件／包身份，不将脚本模型换称真实 DS。
