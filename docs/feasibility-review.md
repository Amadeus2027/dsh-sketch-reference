## 评估结论与证据边界

方案方向确认，架构有条件通过。建议保留“独立 Harness 插件 + 本地 Excalidraw + 官方 DS 视觉建议 + 原生聊天附件”的路线。这里评估的是手绘参考板插件，附件内容与此前所说的“下载插件”不同，下载 PNG 只是一个辅助功能。

**这是实施前评估快照；当前代码与测试进度以 README 和 validation.md 为准。**

已阅读完整方案，查阅赛事官网、两份官方附件及固定版本的宿主相关源码。尚未获得用户插件仓库，未安装插件、未编译、未运行真实 DS 请求。因此不能把源码接口存在、模型文档支持图片视为实机兼容通过。

总体难度中高，主要不确定性在宿主集成，画板本身难度较低。按熟悉 TypeScript/React、有可用宿主和模型配置的条件，原方案 40–60 有效工时可作为开发估算；它不含充分的环境排障、报告和比赛材料缓冲。单人每天仅投入 3–4 小时，无法合理承诺完整首版在当前窗口内完成。

## 产品与创新判断

建议首版主要服务“学生/开发者用草图说明网页布局”的问题。PPT、物体辨识可以保留为用途输入能力，但不增加专项功能，也不作为首版效果评测的主场景。

必须证明的增量是：用户不用离开会话截图上传；可编辑草图和生成时快照明确对应；AI 建议可接到原有开发流程；会话切换、已有文字和附件得到正确处理。画笔、矩形、撤销来自 Excalidraw，应准确归因。

“画板 + 三条建议”容易被看作现成工具组合。工程上的 CAS、nonce 和容量限制有价值，但单独罗列这些机制不能证明用户收益。演示必须展示草图如何影响最终布局，以及相较手工截图上传节省了哪些操作。

## 技术评估与必改项

| 项目 | 判断 | 开发要求 |
|---|---|---|
| Excalidraw 本地编辑与 PNG | 可行，适合复用 | 字体、中文、白底、完整范围导出随最终安装包实测 |
| iframe 隔离 React | 合理 | 保持外壳共享宿主依赖，编辑器独立打包 |
| KV 可编辑保存 | 有实际 API 支撑 | 原子 update 可用于现有记录 CAS；初次创建仍需互斥；保留 pending 恢复 |
| 原生图片草稿 | 高风险但有实现入口 | InputActions 只接受附件 ID；createDrafts 在控制器实现中存在，实际注入可达性必须验证 |
| 左右分栏 | 有 slot/factory 边界，回归成本较高 | 验证真实会话状态、权限等待、生成中、关闭恢复；不靠 DOM 强改 |
| DS 看图建议 | 文档与 provider 支持此路线 | 实际账户权限、请求格式、终止事件与真实图像理解仍须实测 |
| 复用 dsh-diagram | 合理但不能直接宣称兼容 | v0.6.1 的发布验证针对较旧宿主，需要移植及重验 |

**必须修正认证路线。** 原方案 §0 宣称复用账户或 API 配置，但 §8.1/§12.3 固定 deepseek-official。官方 provider 文档说明 deepseek-official 使用 API Key，deepseek-account 使用账户授权，二者不互相回退。首版可在已有官方 DS 路线中明确选择建议模型，校验图片能力；选定后本次请求固定路线。不要把“支持官方 DS”实现成只支持 API Key，也不要擅自要求账户用户再配 Key。自定义网关不纳入首版承诺。

来源：[官方 provider 说明](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.1-alpha.1/packages/llm/llm-deepseek/README.md)。

**明确引用图片一致性。** 用户取得建议后又改图，不能将旧 actionPrompt 与新图片无提示组合。保留过期标识；点击使用时比较图与用途，要求重新获取或明确采用旧快照。即使使用有效建议，随后再次改图，也要在加入图片前提示建议与图片可能不匹配。首版无需自动替用户选择。

**离线中文要验证覆盖率。** “字体已打包”不能证明常见中文都不依赖系统回退；检查实际字体字符覆盖、字体许可和导出结果。若包体/授权不合适，限定已测操作系统并如实说明，不能宣称全平台离线中文支持。

**协议需补齐。** 文档描述取消按钮，但 RPC 表没有取消接口。单窗口可以依靠 abort fetch 与断连传播实现，须写清并实测；共享请求订阅是可后置的优化。多个窗口使用相同 localStorage key 的 pending 草稿可能互相覆盖，应加入窗口身份并保留冲突副本。

**附件存储增长不能只看索引配额。** 淘汰 snapshot 索引不一定释放 PNG。首版至少避免不必要重复保存，记录容量边界；不明确引用关系时不全局删附件。将长期清理作为后续维护项。

可继续采用方案中的单次建议、独立请求、终止状态检查、受限 schema、取消与总超时。固定版本 llm-retry 的默认执行器挂在 agent/request-error 上，不能假定独立建议调用会自动获得主代理重试。

源码依据：[输入契约](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.1-alpha.1/packages/client/ui-conversation/src/client/contract/input.ts)、[附件控制器](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.1-alpha.1/packages/client/ui-conversation/src/client/service.ts)、[slots](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.1-alpha.1/packages/client/ui-conversation/src/client/contract/slots.ts)、[KV](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.1-alpha.1/packages/storage/storage-domain/src/domain.ts)、[重试执行器](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.1-alpha.1/packages/llm/llm-retry/src/index.ts)。版本依据：[Harness 预发布](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.2.1-alpha.1)、[diagram v0.6.1](https://github.com/hanzhangzzz/dsh-diagram/releases/tag/v0.6.1)。视觉依据：[DeepSeek 视觉文档](https://api-docs.deepseek.com/guides/vision/)。

保留：桌面左右布局、自由画和文字、一会话一草图、自动保存与恢复、白底 PNG、真实 DS 建议位于画板上方、插入建议、原生附件加入、会话与旧建议保护、可安装 tgz、必要错误恢复及来源记录。

后置：多人协作、实时 AI、自动改画板、历史快照界面、模板市场、SVG/PPT 导出、远程平板部署、跨版本兼容、上游 PR 合并。自动缓存及复杂共享任务可在核心稳定后增加。保留单飞、超时、取消、CAS、基本容量限制，不以缩减范围为由静默丢图或发错会话。

“一次出可用版”应理解为首次正式交付就包含完整闭环和已验证安装包；实现内部仍需分阶段构建与验证。

1. 从干净 profile 安装 tgz 后能画、输入中文、保存、重启后继续编辑。
2. 实际 DS 分析指定草图，能识别图上独有的标签和相对位置；不使用假卡片。
3. PNG 加入原生输入框，用户已有文字和附件保持；正常发送后模型确实收到图片。
4. 请求过程中改图、切会话、关闭、断网均不会丢当前图或把内容加入另一会话。
5. 关闭或卸载后聊天、生成和权限交互正常。
6. README 标明已测宿主、系统、浏览器、凭据路线、安装方法和限制；未测项目不声称兼容。
