# 0.3.0 批注同步稳定性补齐

日期：2026-10-09（北京时间）。基于 main `7beb9a6`，包含已合并 PR #6 的分页与恢复副本修复。本轮继续 P0，不开放画板修改工具，不增加模型服务、依赖或存储/RPC 版本。

## 修复前实际复现

使用 main 构建 tgz、隔离 DSH Web profile 和真实 Excalidraw。仅模型响应为脚本；Playwright 拦截测试页面的批注 RPC，不改宿主模型配置。

1. `agent/update` 返回测试 503，随后 `agent/get` 也返回 503。点击“刷新 Agent 批注”后，原代码先清空 pending，导致重试按钮消失、关闭保护失效。断言 `0 !== 1`，不是通过模拟模型推断缺陷。
2. 持有已读取的 open 状态响应，再成功保存 resolved；释放旧响应并暂缓下一次读取。原代码把刚确认的 resolved 覆盖成 open，UI 断言失败。实际服务器已保存的状态没有回滚，但 UI 会短暂误显示，可能引导错误的后续操作。

复现过程中的夹具路由释放顺序和安装客户端版本不匹配已分别修正；只有明确命中上述功能断言的结果才作为缺陷证据。

## 最小修复

- `src/editor/agent-comments.ts`：刷新返回是否取得可用工具服务的有效快照；失败或服务不可用时保留 pending、重试和关闭保护，保留已知批注，不把 unavailable 当作空批次。
- 使用本地写入序号丢弃写入开始/确认之前的过时读取，通过原有单任务/事件合并循环再读当前状态；没有定时轮询。
- 同步引用保护在途保存；刷新完成后只清理它开始时选中的 pending，避免清掉期间新发起的修改。
- `src/host/tools.ts`：明确 expectedBatchId 使用 JSON null 而非字符串 "null"。继续严格校验，没有宽松转换或移除批次 CAS。文案对真实模型重试率的改善未实测。

## 新增验证范围

`test:browser:agent` 增加：保存执行前失败、保存已提交但返回响应丢失、刷新失败、工具服务不可用、同 mutationId/CAS 重试、迟到读取、SSE 断开与手动重连。检查草图 revision 不变、服务器状态正确、连接恢复后数量为 1，且没有额外独立分析。

`test:browser` 现在实际下载 PNG 和 `.excalidraw`，浏览器解码 PNG，校验备份格式版本及与保存场景相同的元素 ID、坐标、尺寸和中文文字。该验证不等于插件支持导入：原生加载场景入口仍关闭。

新增单测验证字符串 "null" 被拒绝且不写草图/批注，修正为 JSON null 后可成功。原 97 项测试保留，当前共 98 项。

### PC 手动复验

1. 在独立 Web profile 安装该 PR 构建包，保留正常模型配置；不要把测试模型覆盖层放入日常 profile。
2. 绘制形状和中文，用原生聊天请求解释/批注。解决、重开批注，关闭重开并重启宿主，核对状态和当前会话隔离。
3. 保留原聊天文字和附件，下载 PNG 与草稿备份，再加入参考图，核对文件、中文和已有输入；不同平台须分别记录。
4. 若复验失败/迟到响应，使用仓库的隔离测试 profile 和 `test:browser:agent` 故障夹具。普通网络断开不保证触发准确的写入/读取交错，不能代替该回归断言。
5. 真实模型的通用理解、锚点语义质量和路线差异按下一节逐项记录，仍须区分“调用链成功”与“答案正确”。
