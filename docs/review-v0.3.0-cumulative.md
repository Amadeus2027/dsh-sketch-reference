## 可复现缺陷

### F1 / P2：摘要分页可能返回零进度

位置：`src/host/agent.ts:38–43`，尤其第 42 行。

合法输入触发条件：用途为 2000 个 `\u0001`；两个 text 元素，其 ID 各长 256（数字前缀，余下为 `\u0001`），文字各为 240 个 `\u0001`；一个指向第一元素的 Agent 批注，标题为普通短文本、理由为 120 个 ASCII 字符。场景先经 `drawingSchema.parse` 验证，再通过真正的 `SketchAgent.annotate/read` 执行。

复现返回：`elements=[]`、`annotations.items.length=1`、`truncated=true`、`nextOffset=0`，JSON 共 **5527 字节**。虽然未超出 8KiB，却无法按返回游标继续前进；重复读取会重复同一页，结构元素不可达。

原因：先保留不超过 2KiB 的批注，再为整体预算删除元素。最后一个元素被删除后游标回到当前 offset，之后也不会重新分配已经释放的字节预算。现有“转义文本 + 批注”测试使用三个特别大的批注，批注项目先全部被裁掉，未覆盖“恰好保留一个较大项目”的组合。

建议：预算不足时优先裁剪可选批注，确保至少返回一个元素；确实无法返回时提供明确的受限错误或可用读取方式。对任何截断分页断言 `nextOffset > offset`，增加上述组合回归，避免静默循环。该问题需要特殊但协议允许的数据，不代表普通短文本样例也失败。

### F2 / P2：跨标签页恢复过的旧副本仍会被再次提示恢复

位置：`src/editor/pending.ts:11–25`；调用方 `src/editor/App.tsx:80–83,147–149`。

复现：旧标签页 A 留下恢复副本并关闭；新标签页 B 调用 `recoverPending` 选中 A 的副本，恢复并成功保存；B 再修改、保存新内容并调用 `clearPending`；下次重新打开时，`recoverPending` 仍返回 A 的旧副本。

原因：扫描会选择同一 owner 的全部标签页副本，并返回来源 `key`，但成功恢复的调用链没有消费这个来源 key；`clearPending` 只清理当前标签页。副本与后续服务器内容不同后，又会出现“发现未保存的恢复副本”。版本冲突保护仍存在，未观察到服务器被自动覆盖，但会反复提示过时内容、冻结编辑等待选择，并可能让用户导出错误版本。

建议：恢复成功且服务端确认保存后，按选中的来源 key 与原快照做比较后消费该副本。保留其他标签页更新后的内容，不能通过清空同一会话所有副本来规避问题。补充“另一标签页恢复 → 保存 → 再编辑保存 → 重开”测试。

## 真实模型质量观察

除首轮两元素中文样例外，本次新增一个无文字标签的八笔手绘房屋样例，提示要求解释可见事实与推测，并只读核对结构。画板在原生 Agent 调用期间关闭；实际轨迹只有 `sketch_read` 的 summary 和两次 elements，没有 annotate。

模型识别出房屋/门的含义、八个 freedraw、没有 text 元素，并说明结构不含点序列、图片语义不能完全由结构核对。页面显示完成用时 40 秒。但同一回答同时写“单坡顶小房子”和“屋顶两坡”，存在语义矛盾。此结果证明图片与结构链路可用，不能证明物品/数学/流程/机械草图的理解质量已经全部通过。

插件重新启用后另一次真实读取完成，页面显示 5 秒，仍为八个 freedraw。当前两个会话是人工/工具引导的小样本，不足以统计准确率、延迟稳定性或节省比例。
