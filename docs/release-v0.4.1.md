# 0.4.1：自然讨论批注的维护补丁

基于 main `9bcad5f`（0.4.0），不升级 DSH `0.2.1-alpha.1`、Excalidraw `0.18.1` 或其他依赖，不迁移草稿数据。

## 交互变化

以前追问会插入批注全文、revision UUID 和元素 ID；现在示例为：

> 关于画板上的「顶部区域」（聊天批注·012345abcdef），为什么你这样判断？

纠正和修改入口提供可编辑的中文占位文字，修改仍要求先提议、等待确认。保留原生 Composer 的文字、选区保护、附件及手动发送行为。

公开输入桥只支持文本插入，没有供插件附带隐藏 Agent 上下文的接口。因此保留一个最小短引用，不只按标题或序号关联：确定性摘要绑定真实会话、revision、批注来源、批次和批注 ID；沿用 `sketch_read` 的可选 `commentReference` 参数解析到真实 `discussion.elementId`。插入前、读取时均验证当前记录；失效、忽略、删除、非当前重点或歧义引用拒绝解析。无需新增模型、工具、存储表或图片传输。

批注操作增加立即去重和“正在打开聊天…”反馈；失效与删除锚点分别显示。继续复用整卡点击、原生按钮的 Enter/Space、现有覆盖层与 Excalidraw 定位 API。

修改提议区分待预览、已预览待确认、需重新提议、已忽略和历史应用记录。撤销或继续编辑后显示“曾应用 · 画板已变化”；预览图标为历史效果。现有 Agent 读取结果也明确 `applied` 是历史回执，当前状态以本次读取场景为准。CAS、用户确认、备份和原生撤销保持原实现。

## 保留与边界

- 原生布局、视觉缓存算法无需修改；本轮对照与针对性回归未发现需要改动的证据。
- 待发送 PNG 跨会话未恢复在完全卸载插件的原生 DSH 中也复现；文字恢复、PNG 丢失的结果与安装插件一致，不接管宿主附件管理。
- 不新增“悬停画板元素反向高亮卡片”：固定版本公开指针回调提供坐标，未提供可靠元素命中结果；不使用私有 API 或自建命中引擎。
- 短引用是可见的最小关联信息，并非权限凭据。仅解析当前合法范围内唯一匹配项；更新批次或 revision 后需从画板重新选择。
- 历史提议说明不会判断用户是否确实执行过撤销；只提示当前 revision/草图已变化，避免把历史效果当成当前状态。

自动检查、安装回归、真实 DeepSeek 调用及未覆盖范围见 [Windows 验证记录](windows-validation-v0.4.1-20261010.md)。合并由维护者执行，本补丁不自动发布。
