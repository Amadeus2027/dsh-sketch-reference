# 0.3.1 → 0.3.2 固定场景采样

2026-10-09，Linux 云端，Node 24.19.0 / pnpm 11.19.0 / Chromium 151 / DSH Web CLI 0.2.1-alpha.1，Excalidraw 0.18.1。两版均从独立 profile 的真实 tgz 安装运行，旧版 410 个 lib 文件与 0.3.1 交付包一致，新版 415 个 lib 文件与本次构建一致，注入客户端均为 138,080B。

同一 `tests/browser-performance.mjs`，1600×1000 视口、250 个固定矩形、平移/修改各 50 帧、3 次 PNG 导出、5 次关闭重开。每组 3 轮、每轮新浏览器上下文；未调用模型。先测 0.3.2 收尾前版本，再测 0.3.1，补齐矮窗口菜单样式后重新安装并测最终 0.3.2。下表使用旧版与最终交付组；早期 3.2 首轮与另一隔离安装重叠的 724.7ms 慢样本仍保留在 final 组原始记录中。宿主 profile、缓存/GC 和机器负载未完全控制，**不能据此归因整体提速或退化**。Windows 还需同机重复采样。

帧间隔来自公开 updateScene 的 rAF 驱动，不等于真实鼠标绘图 FPS；heap 是共享 renderer 的单点采样，不是插件独占内存或泄漏检测。PNG 时间含菜单动作与浏览器下载事件，RPC 时间含宿主存储。没有模型延迟、实际 input Token 或节省百分比。原始文件保留全部轮次：`performance-031-baseline-{1,2,3}.json`、早期 `performance-032-final-{1,2,3}.json`、最终 `performance-032-delivery-{1,2,3}.json`，均为数值与非私密状态，不含会话/登录 URL。

本轮可验证的收益是新选区视觉流程复用成熟导出器，同一快照只缓存全图及一个重点；重复准备只一次光栅化和原生 saveImage，关闭画板的工具读图不再导出。该结论来自 browser-visual 的实际计数；不据其推算真实模型 Token 节省。

复现：先把对应构建包安装到独立 Web profile，核对安装 `lib/client.js`，启动本地宿主。只在终端环境设置私密的 `DSH_SMOKE_URL`，不提交该值。

```sh
DSH_PERF_LABEL=032-final-1 pnpm run test:performance
# 测另一安装版时，DSH_PERF_CLIENT 指向该 profile 安装的 lib/client.js
```

重复三轮，保存 ignored test-results 中的原始 JSON，记录硬件/视口/浏览器/缩放/宿主/构建 SHA256。更严格的比较应交错测量、固定负载、分别记录冷/暖缓存及 GC，不能把此次中位数差直接写成作品效率提升。
