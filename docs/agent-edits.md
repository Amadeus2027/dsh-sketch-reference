# v0.3.1 受限 Agent 修改与重点协作（候选包）

2026-10-09，北京时间。基于包含 PR #7 的 main `d17ef70`。用户授权先完成云端功能开发，将真实 DeepSeek 与 Windows 效果集中留到后续验收；各阶段仍执行单测和隔离宿主浏览器回归。没有发布版本。

## API 审计与范围

固定 DSH `0.2.1-alpha.1` 和 Excalidraw `0.18.1`。沿用官方 `defineTool`、执行上下文中的会话头、`ctx.tools.register` 和现有失效 SSE；未升级依赖、增加密钥/模型服务或复制社区实现。原 P0 的读取、批注和原生附件/输入工作流保留。

编辑器仅调用 Excalidraw 公开 `convertToExcalidrawElements`、`newElementWith`、`restoreElements`、`updateScene`、`CaptureUpdateAction.IMMEDIATELY` 和现有导出能力。构造器负责原生创建与不可变更新，公开恢复器仅提供合并场景的有效排序索引，保留原有几何与绑定，正式应用一次捕获历史；不调用内部绑定函数，不实现绘图、拖动、缩放或渲染引擎。`history` 公开接口只有 clear，未伪造 undo 方法或清空历史，撤销通过原生交互完成。

首版创建矩形、椭圆、菱形、文字与向右下的直箭头；移动独立元素；仅缩放独立矩形/椭圆/菱形；删除独立元素。锁定、分组和绑定目标（包括其他元素对目标的绑定）被明确拒绝，用户仍可手工调整。文字尺寸交给原生字体测量，未开放任意字体/样式、绑定操作、场景 JSON 或代码输入给模型。

元素细节附加紧凑 editRestriction（none/locked/grouped/bound），与操作准入复用同一判断；重点读取仍以完整场景检查外部绑定。模型能在提议前看到限制，不需要靠反复失败发现目标不可修改。这是程序权限信息，不是重算绑定几何。

## 提议、确认与恢复

`sketch_propose_edit` 输入 revision、expectedProposalId（UUID 或 JSON null）、summary 和最多 20 条严格操作，总 JSON 不超过 16KiB。会话取自官方 Agent 上下文，不接受模型指定 owner。`sketch_read` 仅附加紧凑提议状态，不把完整修改前场景送入模型。

提议存入独立 `sketch_edits` version 0 域，每完整 owner 最多一个记录，包含 id、baseRevision、before（恢复快照）、goal、summary、operations、createdAt、status 和工具重试摘要。最多 500 个记录、128MiB；当前草图和原批注存储格式不变。旧插件不读取新域。新域打开失败时保留读取/批注及基础绘图。

Agent 没有 apply 工具。用户打开画板，手动展开提议、生成静态 PNG 预览，再点击“确认应用修改”。预览和修改前备份均不污染正式场景。应用前冻结画板、完成原自动保存并核对本地版本、用途与快照；宿主再次检查提议身份及草图 CAS，校验候选场景只包含受限操作的变化。

实际应用复用 Repository.save 的 CAS/幂等写入，mutationId 为提议 UUID；收到确认后 Autosave 才接纳新 revision，并通过原生 updateScene 捕获一次撤销。任何失败保留手绘/保存/导出；未确认的应用结果阻止直接关闭，允许相同候选重试或保留备份后载入服务器版本。已应用、已忽略、已替换或过期的提议不会覆盖新草图。

草图与提议状态位于两个表，未宣称跨表原子事务。若草图已写入而状态保存失败，按草图 mutationId 核对已提交结果；同一候选重试补齐 receipt，不再写第二份草图。若之后已有更新，拒绝覆盖。修改前快照可在关闭重开后下载，原生撤销历史本身不会跨刷新持久化。

提议事件读取携带已知 id/status：未变化时只返回约束内的 unchanged 响应，不重复传输完整恢复快照。只有新提议、状态改变或重新打开画板才需要完整结果。它减少的是插件通信量，未用此推算模型 Token。

## P2 的最小重点协作

原生选择或框选后，通过“更多操作 → 选区作为重点”主动设置。不实现新的选择/框选工具，不在每次 selection/onChange 上发送请求。最多 50 个元素（包括必要的绑定文字）；宿主只在内存保留最近 100 个完整 owner 的重点，未修改任何草稿/建议摘要或存储格式。草图 revision 改变后明确失效，用户可清除或重设；关闭画板仍可读取，宿主重启/工具服务停用后清除。

`sketch_read` 默认 scope=all，只附加重点数量、版本与过期状态；用户询问已设置重点时，可使用 scope=focus 和已读取 revision，分页/输出字节限制保持原样。scope=focus 不与 elementIds 混用。绑定文字作为必要语义上下文纳入，其他连接图形未自动扩展；必要时渐进读取完整场景。结构不替代自由手绘图像，未新增区域裁图或关闭画板后的 PNG 工具。

本轮 0.3.1 候选纳入 P1 与 P2 的最小选区能力，原规划中的“0.3.2 选区”不代表已发布的版本。复杂修改历史、绑定编辑和实时多人协作未开发，仍按原定非首版范围处理。

## 阶段证据与限制

P1 单测覆盖提议幂等与 CAS、真实变化白名单、会话隔离、取消、草图写入后状态失败、只开放官方提议工具、外部写入接纳与撤销后的自动保存。Linux 实装浏览器使用真实 DSH、工具执行、存储和 Excalidraw，模型响应为脚本：确认前不写入、旧版本拒绝、五类原生创建及移动/缩放/删除、一次撤销、丢失响应的同提议重试、恢复备份实际下载、会话切换和忽略通过。最终候选包全套回归见 validation.md 的 2026-10-09 追加记录。

集成测试实际发现并修正文字 `containerId: null` 白名单误拒绝，以及公开转换器对箭头端点的半像素微调校验不兼容。保留原生输出，端点校验限定在构造器允许的微小范围。延迟稳定性探针还复现单个构造器产生重复排序索引、原生 updateScene 修复后触发第二次保存的问题；改为保存前从公开 restoreElements 获取有效索引，避免自行实现排序或重新计算几何。测试夹具的静态/交互画布点击与初始化历史模式也已修正，不把这些夹具问题作为插件功能缺陷。

真实模型是否能自主选择工具、正确生成提议和理解复杂图形仍未验证；inputTokens 继续为 null。账户路线、真实限流/超时、Windows、PTC/both、其他插件组合和热卸载继续待验收。未声称性能或 Token 节省比例，修改前完整快照仅用于客户端恢复，不作为默认模型上下文。

## 手动验收

1. 独立 profile 安装候选包，使用已有 DSH 官方模型配置；不加载测试模型覆盖层。
2. 画任意草图，等待保存，在原生聊天请求移动/添加图形。自由手绘理解仍通过“作为参考发送”提供 PNG。
3. 核对只有 sketch_read/sketch_propose_edit，正式画板在确认前不变；预览后确认，再用原生撤销。
4. 编辑草图后再确认旧提议，核对拒绝；两窗口同版本确认最多一个实际写入。
5. 下载修改前备份，刷新/关闭重开/重启核对场景、提议与原批注；不要把原生撤销历史描述成可跨刷新恢复。
6. 网络或模型失败时，继续手工编辑、导出和原生附件；应用结果不确定时重试或载入服务器版本，不直接覆盖。

自动复现：将 overlays/fixtures 放入隔离安装 profile，按 validation.md 启动固定版宿主，执行 `pnpm run test:browser:edits`。不提交登录地址、凭据或私人会话日志。

## 本轮性能样本与未验收项

固定视口 1600×1000、250 元素、50 帧手势、真实隔离安装宿主，无真实模型调用。仅一次冷开/一轮绘图样本，不用于声称比 0.3.0 提速；历史对照的机器负载与采样时间不同。原始数据见 [性能样本](benchmarks/performance-edits-final-1.json)，复现用 `DSH_PERF_LABEL=edits-final-1 pnpm run test:performance`。

| 指标 | 当前样本 |
| --- | --- |
| 首次打开 | 385.9 ms（1 次） |
| 关闭重开 | 中位 218.9 ms，200.2–500.0 ms（5 次） |
| PNG 三次导出 | 66.5 / 81.6 / 55.0 ms，实际光栅化 1 次 |
| 保存 HTTP 往返（不含 debounce） | 54.4 / 47.0 ms（2 次） |
| 编辑 50 帧 | 1 次保存 RPC，9 次恢复副本写入，帧间隔 P95 25.6 ms |
| 平移 50 帧 | 0 次保存/恢复写入/哈希，帧间隔 P95 16.8 ms |
| 打开前编辑器请求 | 0 |
| 宿主注入客户端 | 138,080 B，与历史 0.3.0 相同 |

Renderer heap 开板前约 47.7MB，开板并五次重开后约 94.7MB；包含宿主、编辑器、字体和缓存，未控制 GC，也未隔离插件内存，不据此宣布无泄漏或相较基线改善。两种手势未观察到 long task；不代表所有场景帧率。inputTokens 为 null，未测真实 Token 节省。

一轮 P0 SSE 故障注入等待断开提示超时；同代码重启后完整重跑通过。尚未确认该单次等待失败的根因，保留记录，不标成已修复缺陷或掩盖为稳定性通过。真实模型、其他宿主模式/插件组合、跨平台及热卸载仍需后续统一验收。
