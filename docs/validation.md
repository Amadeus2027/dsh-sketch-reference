## 复现浏览器检查

先创建专用测试 profile（不要使用含真实任务的日常 profile），以官方 Web 模板初始化并安装插件。绑定 127.0.0.1；无桌面目录选择环境时使用 browse-picker 覆盖层，本仓库的 `tests/browse-picker.overlay.yml` 改编自固定版本官方测试覆盖层，可通过 `dsh --profile 测试名 --patch /绝对路径/tests/browse-picker.overlay.yml` 使用。

运行宿主后，将它输出的带 token 登录地址放入 `DSH_SMOKE_URL` 环境变量，执行 `pnpm run test:browser`。登录地址不应提交到 GitHub。可用 `CHROMIUM_PATH` 指定系统 Chromium；脚本会在测试会话中画图与添加输入，但不会发送聊天或请求真实模型。

测试产物放在已忽略的 `test-results/`；单元测试执行 `pnpm test`。HTTP 测试需要本地监听权限。

恢复存储故障检查：在同一专用测试环境中，分别设置 `DSH_SMOKE_STORAGE=denied` 和 `DSH_SMOKE_STORAGE=full` 执行浏览器脚本。故障仅注入插件 iframe；脚本验证持续的备份提示及原有保存、导出和附件流程。

### 实际发现并修复的问题

1. Excalidraw 恢复场景将空 `boundElements: null` 转成 `[]`，导致视觉内容未变却错误过期。先以自动测试复现，再将空绑定统一并在内容摘要中等同处理；真实绑定仍参与摘要。
2. 选中/视口更新回调导致不必要的过期计算和 React/画板重复更新。仅在规范化草稿实际变化时计算过期状态，批注和视口不触发分析。
3. 错误提示改变画板纵向位置，Excalidraw 缓存的偏移可能滞后。容器位置改变时调用公开 `refresh()`，再使用官方坐标转换；浏览器比对实际 DOM 和 API 偏移。
4. DSH 原生新建按钮会复用未发送聊天的空会话，不能据此假设草图隔离测试已创建新会话。测试改为固定版本客户端服务显式创建，并核对会话身份。
5. 宿主模型超时原用 HTTP 408，Chromium 会透明重发同一个 POST（同一 requestId），导致一次点击两次流调用。宿主侧计数先复现，再将模型上游超时改为 504；自动测试约束状态码，浏览器约束四次主动分析只有四次模型流，且绘图/批注操作没有流调用。
6. 本地 file tgz 使用相同路径重装可能复用旧包缓存；测试采用新包路径，核对安装后文件，避免把源码结果冒充安装包验收。
