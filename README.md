# DSH 手绘参考板

在 DeepSeek Harness 会话中画草图、保存可编辑版本，用官方 DeepSeek 理解 PNG、用途和精简元素数据，再把指令和参考图加入原生聊天输入框。定位为 DSH 特化的可视化需求交互插件，可用于物品、数学图形、流程、结构和 UI 等草图讨论；AI 锚点批注是可选增强。

**状态：0.4.0 候选版本，支持从草图批注直接追问、纠正和提出修改，继续使用 DSH 原生聊天。** 修复原生会话内容工厂的滚动与输入框兼容问题，摘要与图中标记独立显示，批注支持整卡点击及元素高亮，修改提供同视角前后对照。草图保存稳定后缓存视觉参考，由 Agent 按需读取，不自动调用模型或发送消息。锁定 DSH `0.2.1-alpha.1` 和 Excalidraw `0.18.1`；尚未正式发布或提交比赛。改动与真实验收边界见 [0.4.0 说明](docs/release-v0.4.0.md)。

本版收敛范围、官方/社区复用与兼容边界见 [0.3.2 实现说明](docs/submission-v0.3.2.md)。下一轮使用 [Windows 全量验收与比赛演示清单](docs/windows-acceptance-v0.3.2.md)，包含安装、恢复、真实模型、修改授权和 5–7 分钟演示流程。

历史 0.3.2 真实 DS 验证累计 27/30 次：[修复验证报告](docs/windows-validation-v0.3.2-ds30-20261009.md) 记录前 25 次，[前端实机验证](docs/frontend-validation-v0.3.2-20261009.md) 记录后 2 次。本轮 0.4.0 的授权、模型调用和实测单独记录在 [Windows 验证报告](docs/windows-validation-v0.4.0-20261010.md)。前端案例与物品识别不证明任意任务正确；此前数学错误、PPT 及其他兼容环境缺口仍保留。

原生聊天仍是主要问答入口；普通提问无需先生成绘图建议。Agent 只能提出修改，必须由用户预览并确认后应用。新增能力、限制和手动验收见 [受限修改与重点协作](docs/agent-edits.md)，初版读取/批注见 [Agent 协作说明](docs/agent-collaboration.md)，旧建议与草稿兼容性见 [批注说明](docs/anchored-comments.md)。

0.3.0 修订继续补齐分页、恢复副本与批注失败恢复；最新改动及真实验收缺口见 [稳定性补齐记录](docs/stability-v0.3.0.md)。

## 安装与启动

需要 Node.js `22.19+` 或 `24+`、pnpm 和本地浏览器。首版只支持 DSH Web 绑定 `127.0.0.1`，不支持远程公开部署。

```sh
npm install -g @deepseek-ai/dsh@0.2.1-alpha.1
# 先运行一次，初始化官方 web profile
dsh web
# 退出宿主后，从下载的 tgz 安装
dsh plugin --profile web add /绝对路径/dsh-sketch-reference-0.4.0.tgz
dsh web
```

从源码构建：

```sh
git clone https://github.com/Amadeus2027/dsh-sketch-reference.git
cd dsh-sketch-reference
pnpm install --frozen-lockfile
pnpm run typecheck
pnpm test
pnpm run bundle
pnpm pack
```

源码开发时可用 `dsh plugin --profile web add /绝对路径/dsh-sketch-reference` 链接安装。不要将插件安装进只有 `dsh-base` 的终端 profile。

卸载：退出宿主后执行 `dsh plugin --profile web remove dsh-sketch-reference` 并重启。卸载不会主动删除草稿和宿主附件；操作前建议下载备份。

## 使用

1. 在 DSH 中选择工作区并创建会话。输入框右侧点击「参考板」。
2. 绘图并填写用途，草稿自动保存；右下角「更多操作」提供 PNG 导出、`.excalidraw` 备份和建议模型选择。
3. 配置 Harness 原有的 DS 账户或官方 API 路线，然后点击「AI 分析草图」。更多操作中的「分析内容」可选图片与结构、仅图片、仅结构；纯结构跳过 PNG 导出与发送，可使用仅支持文本的官方路线，但不能识别自由笔迹内容。每次主动分析单独调用模型，可能产生用量；可取消。模型关联真实元素 ID，插件计算标记位置；不确定时保留全局建议。
4. 分析摘要持续可见，详情默认折叠；点击整张批注卡片定位元素，悬停或键盘聚焦高亮元素，画板编号也能激活卡片。隐藏图中标记不隐藏摘要；仍可解决、重新打开或忽略批注。详情中的「追问」「纠正」「修改这里」把当前批注与真实元素上下文加入原生输入框，保留已有文字与附件，由你编辑并手动发送。
5. 「使用建议」将指令插入原有输入框；「作为参考发送」加入 PNG 附件。最后由你点击 Harness 原有发送按钮。也可以直接发送参考图，无需先生成批注。

通用问答：绘图保存后直接返回原生聊天提问。画板缓存当前有效范围的视觉参考，Agent 按需使用 `sketch_read` 获取结构、`sketch_read_image` 读取对应版本图片；画板关闭后仍可读，不必先点「AI 分析草图」。缓存不调用模型、不发送消息，同版本有效图片不重复上传。缓存失败可在「更多操作」手动更新，也可「作为参考发送」加入 PNG。请求标注时可使用 `sketch_annotate` 添加说明；Agent 批注与独立分析建议分别保留。

修改协作：请求修改时，Agent 可调用 `sketch_propose_edit` 保存最多 20 条受限操作，正式画板保持不变。展开「修改提议」，预览并点击「确认应用修改」后才更新；支持原生撤销和下载修改前备份。草图或用途变化后旧提议显示“需重新提议”并拒绝覆盖。只创建独立基础形状、文字及向右下箭头；只调整独立矩形/椭圆/菱形尺寸，不自动修改绑定、分组或锁定元素，不承诺跨刷新撤销历史。

局部协作：用原生选择/框选工具选中图形，在「更多操作」选择「选区作为重点」，然后在原生聊天提问。局部 PNG 复用 Excalidraw 原导出器。重点只在当前宿主进程保留，绑定 revision，修改或宿主重启后需重新设置；可主动清除。有过期重点时自动缓存停止，不能擅自改读整图。“刷新协作状态”仅读取状态，不调用模型。

已设置重点时，所有 Agent 结构和图片读取（包括请求 scope=all）均限定到重点及必要的绑定文字；重点过期会明确拒绝读取，重点图片缺失时不代用整图。批注锚点也不能越过重点。需要整图时，先在画板清除重点。此限制不清除聊天历史或先前附件，也不限制其他宿主工具；用途仍作为用户意图提供，不能据此认定选区外已有节点或分支。

加入参考图要求主聊天选择官方 `DeepSeek Flash` 图片模型。插件不会替你切换模型或自动发送。没有 DS 配置时仍可绘图、保存和导出；不会产生虚构建议。

建议固定对应生成时的草图和用途。修改后建议会标记过期，需重新获取。已加入输入框的指令仍由用户管理，换参考图前应检查是否还匹配。

## 数据与边界

- 可编辑场景保存在宿主 `sketch_reference` 存储域，按会话 ID、创建时间、工作目录隔离；每个会话保留一个草稿与最近一批建议。
- 保存采用版本比较；其他窗口抢先保存时停止覆盖，并提供本地备份与载入服务器版本。
- 编辑快照最多合并 80ms 后尝试保存在当前浏览器的本地恢复副本；显式发送、分析、导出和关闭会先取最新场景。浏览器限制存储或空间不足时会持续提示下载备份，服务器自动保存仍会尝试执行。共享设备使用后请清理浏览器数据；分析将 PNG、用途和受限的可见元素字段发送给所选 DS 路线，不发送无关会话与元素自定义元数据。
- 批注状态使用独立 CAS，不改变草图内容摘要；不把编号或文字写入正式图形和导出图。目标删除后隐藏标记，显示“失去锚点”。移动、解决或打开批注不会调用模型。
- Agent 批注存入独立 `sketch_agent` 域，按同一会话生命身份隔离。Agent 摘要最多 8KiB、细节最多 16KiB、每页最多 50 元素；不自动给每轮聊天注入 PNG 或全量场景。参考附件的更新仍由用户控制。
- 版本绑定视觉引用存入新增 `sketch_visual` 域，每会话全图/重点各一个最新引用，最多 1,000 条、2MiB 元数据。实际 PNG 由 DSH 原生附件库保管，二进制历史对象不在此元数据上限内，回收由宿主管理。全图重启可读；重点需重设。模型路线须真实支持 image，否则工具明确拒绝；不自动换模型。
- 结构输入最多 200 个有效元素、元素文字最多 160 个码点、元素列表最多 48KiB；超过时截断，未提供 ID 的建议只能退化为全局建议。仅支持元素锚点，区域坐标定位暂未开放。
- 最多 2000 元素、场景 2MiB、PNG 2MiB、500 个草稿、草稿存储 128MiB；分析全局并发 2、每会话每分钟最多 6 次、默认超时 90 秒。
- 禁用嵌入图片与外部资源，不执行建议中的文本。字体随包提供，绘图与导出不要求连接 CDN。
- 分栏使用官方会话内容工厂；头部以固定版本的公开插槽登记信息映射到私有插槽，保留其业务接口。订阅公开插槽登记变化，动态同步头部扩展。暂不承诺与其他替换 `main.conversation` 的插件共存。
- 模型分析产生的宿主附件由宿主管理；首版没有实现附件长期自动回收。不是训练新模型的项目。

原生集成审计、社区参考、性能原始数据、保存边界与手动验收见 [原生化与性能说明](docs/native-integration.md)。
